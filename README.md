# C-015 | 打つ距離（Golf Yardage）

iPhone Safari 向けのサーバーレス・静的 Web アプリ。**個人利用・非商用向け**。GitHub Pages で配信でき、ホーム画面追加後は、オフラインでも画面・計算・前回取得済みの予報を利用できます。API キー・ログイン・広告・アクセス解析・追跡 SDK・外部 JavaScript ライブラリはありません。

## できること

- 直線距離（yd）・高低差（％）の補正。球筋モデル／シンプルを選択可。上り／下りはボタンで選び、数字を入れ直しても選択を保持。欄には符号なしの数値だけを表示。`-5` と直接入力した場合は下りを選択し、欄には `5` を表示。
- 「向きを測る」で打つ向きを取得し、予報の風向からアゲインスト・フォローと左右の成分を自動計算。測定からの秒数を表示し、3分で未測定に戻す。測れない場合は従来の「アゲインスト・フォロー・横風」を選択。
- 気温と風速（m/s）は予報から自動入力、手入力も可。体感の風速を「−1」「＋1」で調整すると「手入力」表示（0m/s未満にはしない）。
- 風のボタンは「アゲインスト・フォロー・横風」。結果に「アゲインスト 2.8m/s・左から 2.8m/s」「フォロー 1.0m/s・右から 0.5m/s」のように表示。横の成分は距離補正に含めない。
- 高低差・気温・風の内訳、補正後の距離、平らな距離の番手→補正後の番手、補正距離の前後のキャリー。
- 1W〜58° のマイキャリー・基準気温（初期30℃）を端末保存。推定値は「推定」表示。設定を JSON の文字列で書き出し／読み込み。
- 60〜230 yd（10 yd刻み）、−12〜＋12％（±3・6・9・12％）の早見表。セルを押すとショット画面に反映。
- ゴルフ場を名前で検索／位置情報から登録／緯度経度で登録。Google マップの `34.5111495, 135.5865954` のような数字を1行で貼って登録でき、緯度欄に貼った場合も緯度・経度へ分ける。登録済みは端末の localStorage にのみ保存。
- 日本語変換中の Enter は検索せず、検索ボタンまたは変換確定後の Enter で検索。エラーと「1秒に1回まで」の案内は検索結果欄にも残して表示する。
- 日本時間のラウンド日とスタート時刻、スタート時刻から5時間の時間別予報（08:20開始なら08〜13時の6行）。ラウンド中なら現在時刻（時間単位）、開始前ならスタートの時間の行を自動選択。行のタップで上書き。
- Open-Meteo 取得予報を最大4地点分、取得時刻付きで localStorage に保存。ネットが切れた場合はその保存済み予報を表示。画面は Service Worker でキャッシュ。

## 重要な制約

1. **競技ラウンド中の本アプリによる高低差補正・推奨番手表示は使用不可**。ゴルフ規則 **4.3a** では距離・方向や外部の天気予報を知ること自体は認められますが、**高低差の測定と、位置に基づく距離・番手の推奨処理**は禁止されます。公式規則に従うラウンドではこのアプリを使用しないでください。練習・ルールを適用しない私的な試行向けです。参考：<https://www.randa.org/en/rog/the-rules-of-golf/rule-4>
2. 数値は独自の簡易弧モデル、気温・風の補正係数による**推定値**です。打ち出し条件、実際の飛球、標高、空気圧、湿度、突風の方向変化、地形遮蔽、ライはモデル化しません。突風は**表示のみ**で計算に入れません。
3. 風向（気象情報の「北西の風」等）は風が**吹いてくる方角**、矢印は**吹いていく方向**を示します。「向きを測る」で打つ向きを取得した場合は両者から風の成分を計算します。方位・予報の風向が使えない場合は、アゲインスト・フォロー・横風を本人が選びます。
4. ラウンド日は**今日から16日先**まで入力できます。しかし Open-Meteo の通常予報は最大16日間（**通常は今日を含むため今日＋15日まで**）です。**今日＋16日**や、提供時刻のない5時間の行には架空の気温・風速を入れず、**予報なし**と表示し、手入力は使用できます。参考：<https://open-meteo.com/en/docs>
5. 「現在地を使う」は iPhone に位置情報の使用を許可したときだけ GPS を取得します。取得地点はコースの中心ではない可能性があります。位置情報と登録地点は端末の localStorage に保存され、Open-Meteo へ選択地点の緯度経度が送信されます。**名前検索を使う場合のみ**ゴルフ場の検索語が Nominatim に送信されます。
6. 初回の表示・Service Worker の準備・新規ゴルフ場検索・予報更新には通信が必要です。保存済み予報は古くても自動的に最新化されるわけではないので、取得時刻を確認してください。Safari の「履歴とWebサイトデータを消去」などで保存データが失われる可能性があります。
7. **予報の無料 API は非商用利用のみ**。営利アプリ・広告や有料機能付きへの転用は禁止／別契約が必要です。参考：<https://open-meteo.com/en/terms>

## Nominatim 公開 API の条件（2026-11-23 確認）

公式利用規約：<https://operations.osmfoundation.org/policies/nominatim/>

- `https://nominatim.openstreetmap.org/search` を**ユーザーが検索ボタンまたは変換確定後の Enter で検索したときのみ**使用。変換中の `event.isComposing` または `keyCode === 229` の Enter は無視。文字入力中のオートコンプリート、裏側での定期・大量・格子検索は**なし**。
- **1秒に1リクエスト以下**。ブラウザで最終検索時刻を記憶し、1秒以内の再検索を防止。同じ検索語の結果は端末に最大30日キャッシュし、重複リクエストを減らします。
- **HTTP Referer または識別可能な User-Agent が必須**。ブラウザ JavaScript では User-Agent を任意設定できないので、公開された HTTPS GitHub Pages の **Referer（サイトの origin）**を使います。ヘッダーを取り除く設定は入れません。環境によっては検索が拒否される可能性があり、その場合は緯度・経度で登録してください。
- **© OpenStreetMap contributors** の帰属とリンクを常時ラウンド画面に表示。検索 API は公開・ボランティア運用であり利用可能性が保証されません。ページで検索結果の地点を確認する必要があります。
- **重要：1秒1回は「利用者全員の合計」に適用**されます。完全静的な個人向け Web アプリでは複数端末・複数利用者をまたいで絶対的な上限を制御できません。**個人少数利用に限定**してください。複数人に配布・一般公開して多数が利用する場合、現設計のまま公開 Nominatim を使うのは**不適合**です。プロバイダー切替または専用インスタンス等が必要であり、その時点では別設計・別PRで審査してください。
- Nominatim のポリシーは予告なく変更され得ます。利用停止要請が来たら名前検索を停止してください（本アプリは手入力・現在地登録が残ります）。

検索エラー・入力不足・通信が必要な場合・1秒の回数制限は、一時的なお知らせと検索結果欄の両方に表示します。結果欄の文は次の検索で更新されます。候補がない場合は「Google マップで場所を長押しして出る数字を貼ると登録できます」と案内します。

## Google マップの数字で登録

Google マップで場所を長押しして出る `緯度, 経度` をコピーし、ラウンド設定の「Google マップの数字を貼る」欄に貼ってください。緯度の欄へ直接まとめて貼った場合も分けて入力します。ゴルフ場名と地点を確認して「この地点を登録」を押します。

緯度は−90〜90、経度は−180〜180の数値を受け付け、南緯・西経のマイナスやカンマ前後の空白にも対応します。不正な数字を貼った場合は、以前の座標が登録されないように分割欄を消し、入力方法を表示します。緯度・経度を個別に編集した場合や現在地を使った場合は、その新しい値を使用します。

## Open-Meteo の設定と帰属

- エンドポイント：`https://api.open-meteo.com/v1/forecast`
- `hourly=temperature_2m,wind_speed_10m,wind_direction_10m,wind_gusts_10m`
- `wind_speed_unit=ms`（**m/s** を返す。km/h からの二重換算はしない）
- `timezone=Asia/Tokyo`, `forecast_days=16`
- 取得した時刻は端末保存。風向の表示は16方位、成分計算は丸める前の `wind_direction_10m` を使う。
- 帰属：**Weather data by Open-Meteo.com**（[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)）。気象データの正確性は保証されません。公式：<https://open-meteo.com/en/docs>、<https://open-meteo.com/en/terms>

## 向きの測り方

1. ラウンド設定から風向を含む予報を取得する（保存済み予報でも可）。
2. スマホの画面を上にして平らに持ち、スマホの上の端を旗に向けて「向きを測る」をタップ。測定が終わるまでそのまま保持する。
3. iPhone Safari は初回タップ内で `DeviceOrientationEvent.requestPermission()` を呼び、許可後の `webkitCompassHeading` を読む。北の `0°` も有効。取得した向きと「○秒前に測定」を表示し、測定成功から3分（180秒）たつと向きを消して「未測定」に戻す。距離や高低差の入力順・入れ直しで期限は延長しない。測り直した場合はその測定成功から3分間有効。
4. HTTPS（ローカル確認は localhost）が必要。非対応・許可拒否・6秒以内に読み取れない場合も「アゲインスト・フォロー・横風」を選べる。手動選択は測定中・測定後の自動設定を解除する。他の対応ブラウザでは北基準の絶対方位のみ使い、相対的な `alpha` は使わない。

画面がバックグラウンドにある間に期限が過ぎた場合も、復帰時と計算前に期限を確認して方位を解除します。期限後は手動の「アゲインスト・フォロー・横風」で計算し、方位による自動補正には測り直しが必要です。

方位と風速の手直しはその画面のショット用で、設定JSONには含めません。GPSによるグリーン登録・打つ向きの自動算出は今回追加していません。

## 計算仕様（4章 (7) の更新）

`w` は風速（m/s）。空または0なら0。方位は北が0°、東が90°。

- 方位を測った場合：`wf` は Open-Meteo の `wind_direction_10m`（吹いてくる方位）、`s` は打つ向き、`d = (wf − s) × π / 180`。`hw = w × cos(d)`、`cw = w × sin(d)`。`hw` の正はアゲインスト、負はフォロー。`cw` の負は左から、正は右から。
- 手動選択の場合：アゲインストは `hw = w`、フォローは `hw = −w`、横は `hw = 0`。横を選んだ場合の成分表示は `横 w m/s` とし、左右を推測しない。
- `hw ≥ 0`：`windAdj(D) = D × 0.01 × 2.237 × hw`
- `hw < 0`：`windAdj(D) = D × 0.005 × 2.237 × hw`

高低差補正後に気温補正を加えた距離を `D` とし、`D + windAdj(D)` を最後に整数へ四捨五入します。途中の角度・成分・距離は丸めません（成分表示のみ小数1桁）。横の成分 `cw` は距離と番手の補正に使いません。早見表も同じ風の条件を使います。

## テスト（ネット不要）

```bash
node --version  # Node.js 20+ 推奨
npm test        # Node標準の node --test。インストール不要
```

`test/yardage.test.mjs` は依頼の全17件の整数結果と既存の番手を照合し、横風・左右・方位の周回・入力検証も確認します（計22件）。`test/compass.test.mjs` は方位センサーと許可処理を**完全モック**し、初回タップの許可要求、0°、拒否、絶対方位、タイムアウト、監視解除を確認します（11件）。`test/weather.test.mjs` はサンプル `test/fixtures/open-meteo.json` で Open-Meteo の `fetch` を**完全モック**し、時刻選択・m/s単位・16方位・エラーを検証します（6件）。合計39件、外部依存のインストールは不要です。

ブラウザ試験は、Python Playwright とローカル Chromium がある環境で `python3 test/browser-smoke.py` を実行します。外部通信と方位をモックし、390×844pxの表示、下り選択後の5→3・クリア後の再入力・直接入力した負数の表示、測定から179秒／180秒の境界、入力順に依存しない期限、再測定・バックグラウンド復帰を確認します。v1.3では変換中Enterの抑制、エラー表示の持続と再検索後の更新、座標の1行入力・緯度欄への貼り付け・登録値の精度・不正値の拒否も確認します。最新の5番に合わせ、風のボタン・結果・説明・早見表の条件を「アゲインスト／フォロー」に統一したことも確認します。既存の風速操作、設定JSON、早見表、Service Worker 経由のオフライン再起動も検査し、`screenshots/` に画像を生成します。実行結果は `STATUS.md`、`TEST-RESULTS.txt`、`BROWSER-TEST-RESULTS.txt` を参照してください。iPhone Safari実機のセンサー精度・許可画面は別途実機確認が必要です。

ローカルでアプリを開く場合は、`python3 -m http.server 8000` などの静的サーバーを使い、`http://localhost:8000` にアクセスします。`file://` では Service Worker や module scripts が期待通り動きません。iPhone実機は HTTPS GitHub Pages 上で確認してください。

## GitHub Pages の公開手順（本人が行う）

1. `golf-yardage` リポジトリにこの内容のブランチ（例：`feature/c-015-golf-yardage`）を作り、**main を変更せずPRを作成**。差分とテスト結果を確認してから、本人がマージ判断。
2. マージした後、対象リポジトリの **Settings → Pages** を開く。
3. **Build and deployment → Source → Deploy from a branch** を選ぶ。
4. **Branch = `main`、Folder = `/(root)`** を選び、**Save**。
5. 表示された `https://<ユーザー名>.github.io/golf-yardage/` の URL から iPhone Safari で開く。ラウンド・気温・風・飛距離を試す。
6. Safari の共有メニュー（四角から上矢印）→ **ホーム画面に追加**。一度オンラインで開いてから、機内モードで再起動・前回予報を確認。

**GitHubプラン注意**：GitHub Free で Pages を使う場合、通常は**公開リポジトリ**が必要です。プライベートリポジトリでの Pages は GitHub Pro／Team 等の対象プランが必要です。**Pagesサイト自体は通常公開アクセス可能**なので、秘密・個人情報はリポジトリに入れないでください。公式：<https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site>
